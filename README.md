## Практическая работа №2

### Поведение главного класса

**Метод 1:** `AddDostizhenie(int skolko)`
**Что делает:** Прибавляет к счетчику достижений конкретной игры то число, которое мы ему передали. Обновляет статистику игры в нашем каталоге.

**Метод 2:** `igral()`
**Что делает:** Проверяет, запускал ли я вообще эту игру. Если поле `Proces` (часы) больше нуля, возвращает `true`.

**Метод 3:** `ProverkaProhozhdeniya()` *(проверка пройдена ли игра)*
**Что возвращает:** Возвращает строку (например, "Пройдена" или "Не пройдена") в зависимости от того, сколько часов я в ней провел.

**Почему эти действия относятся именно к этому классу:**
Так как мы делаем каталог моих игр, класс `games` представляет собой карточку конкретной игры в этом каталоге. Количество часов, пройдена ли она, и сколько там достижений — это личная статистика именно этой игры.


### Практическая работа №3
`private set` запрещает запись извне, но не рассматривает само число, а значит `Health` проверяется в конструкторе еще и в `Heal`.

`Name = name;` запускает setter: `name` попадет в `value`, после проходит `Trim()` и останваливается в `_name`.

Проверки `0 <= Health <= MaxHealth`:
- `new Hero("...", -100)` -> `Health = 0`, `MaxHealth = 100`
- `new Hero("...", 5000)` -> `Health = 200`, `MaxHealth = 200`
- Александр `150/150`: `TakeDamage(30)` -> `120`, `Heal(10)` -> `130`, `Heal(5000)` -> `150`, `TakeDamage(5000)` -> `0`

### Исправление ошибок

`{ get; set; }` -> `{ get; private set; }`. Внешняя запись больше не компилируется.
`value.Trim(); _name = value;` -> `_name = value.Trim();`. Имя `"   Александр   "` -> `[Александр]`.

### Конец 11 лабораторной README.md

`private set` запрещает писать снаружи, но не проверяет число.

- Снаружи `alexander.Health = -100;` не компилируется 
- Число проверяется внутри класса:
  - в конструкторе — при создании;
  - в `TakeDamage` — не ниже 0;
  - в `Heal` — не выше `MaxHealth`

###  Как работает `Name = name;`

"   Александр   "  →  name  →  Name = name  →  value  →  Trim()  →  _name = "Александр"
